# E-Commerce Recommendation Engine

A production-ready **Hybrid Recommendation System** that combines Content-Based Filtering and Collaborative Filtering to deliver personalized product recommendations — served via a REST API and deployed live on Render.

**Live Demo:** https://e-commerce-recommendation-engine.onrender.com

> Free tier spins down after inactivity — first request may take ~50 seconds.

---

## Why I Built This

Recommendation systems are at the core of every major e-commerce platform, yet most tutorials only cover one approach in isolation. I wanted to build a system that mirrors real-world complexity — handling cold-start users, blending multiple signals, evaluating model quality, and exposing everything through a deployable API. This project demonstrates end-to-end ML engineering, not just model training.

---

## Key Engineering Highlights

- Hybrid scoring: `0.6 × collaborative + 0.4 × content-based` with normalized blending
- Cold-start fallback: new users automatically receive popularity-based recommendations
- TF-IDF with bigrams (5000 features) on product name + category + description
- SVD matrix factorization (50 latent factors) evaluated on 80/20 split — RMSE: 0.4146, MAE: 0.3668
- Models persisted with Pickle for instant API startup (no retraining on each request)
- Confidence scoring (High / Medium / Low) and human-readable explanations per recommendation
- Fully containerized with Docker and deployed on Render

## Recommendation Flow

**Known user (`/recommend/user/U001`)**
1. Fetch all products the user has rated
2. Run SVD to predict ratings on unseen products
3. Take the user's highest-rated product as an anchor
4. Run TF-IDF cosine similarity from that anchor
5. Blend both scores: `final = 0.6 × norm_collab + 0.4 × content`
6. Sort by hybrid score, attach confidence + explanation, return top N

**New user (cold-start)**
1. No ratings found → fall back to popularity
2. Rank products by average rating (min 2 ratings)
3. Return top N with `mode: cold_start`

**Product similarity (`/recommend/product/P001`)**
1. Compute cosine similarity from TF-IDF matrix
2. Return top N most similar products with explanation

## Technical Decisions

| Decision | Reasoning |
|---|---|
| SVD over ALS or KNN | SVD handles sparse ratings well and is fast to train on small-medium datasets |
| TF-IDF bigrams | Captures phrases like "noise cancellation" and "air cushion" that unigrams miss |
| Weighted blend (0.6 / 0.4) | Collaborative signal is stronger when user history exists; content fills the gap |
| Pickle for model persistence | Zero-latency API startup — models load in milliseconds |
| Flask over FastAPI | Simpler setup for a focused REST API; no async requirements here |
| Render over Heroku | Free tier with Docker support and GitHub auto-deploy |

## Engineering Challenge / Hardest Bug

**Problem:** `scikit-surprise` failed to build on Python 3.11 + Linux (Render's environment) with a numpy subarray struct error during C extension compilation.

**Root cause:** `scikit-surprise==1.1.3/1.1.4` had a C-level incompatibility with newer numpy versions on Python 3.11.

**Fix:** Pre-install `numpy==1.26.4` before any other package in the Dockerfile, then use `scikit-surprise==1.1.5` which has the patched C extension. Order of installation in Docker matters — numpy must be compiled first so surprise links against the correct headers.

**Second issue:** Flask was binding to `127.0.0.1` (localhost only), so Render's health checks couldn't reach the port and the deployment kept failing. Fixed by changing to `host="0.0.0.0"` in `app.py`.
